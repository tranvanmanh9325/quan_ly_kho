# Core Collaboration Principles

This document defines the working standards, engineering mindset, and collaboration guidelines between human developers and AI coding agents.

## Human in the Loop

- **AI as an Accelerator**: AI tools and agents serve strictly as development accelerators, not autonomous decision makers.
- **Code Accountability**: Human software engineers must thoroughly understand, review, verify, and be capable of explaining every single line of code generated by AI before committing, merging, or opening pull requests.
- **No Blind Acceptance**: AI-generated proposals, database queries, and schema changes must be scrutinized against system invariants, performance constraints, and business logic.

## Plan Before Code

- **Structured Design First**: Before writing any implementation code or making structural refactorings, formulate a step-by-step plan covering:
  - Domain models and schema implications
  - Serializers and input validation boundaries
  - API endpoints, HTTP verbs, and query parameters
  - Service boundaries and business invariants
  - Automated tests and verification methods
- **Approval Gate**: For major architectural changes or sensitive database interventions, present the plan for review before making irreversible edits.

## DRY and Clean Architecture

- **Don't Repeat Yourself (DRY)**: Eliminate duplicate logic across views, serializers, and utility functions. Shared validation logic and calculations must live in a single source of truth.
- **Thin Views**: Keep ViewSets and API views minimal. Views should only handle HTTP request parsing, permission validation, delegation to service/model layers, and response serialization.
- **Rich Domain Logic**: Encapsulate domain logic, invariant validation, and state machine transitions within Model methods (`clean()`, `save()`) or dedicated service modules (`warehouse/services/`).

## Senior Engineer Mindset

- **Production-Grade Quality**: All code must meet big-tech industry standards for readability, maintainability, performance, and defensive design.
- **Real Verification**: Never assume an implementation works without running live tests and checks (`manage.py check`, `manage.py test`, and smoke testing).
- **Proactive Risk Mitigation**: Anticipate race conditions, database deadlocks, capacity overflow edge cases, and cascade deletion side effects.
